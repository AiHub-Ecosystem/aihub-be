# ADR-0201: Pace recovery across AIHUB tiers and slots

- Status: Accepted; implementation pending
- Date: 2026-11-28
- Related issue: [#631](https://github.com/AiHub-Ecosystem/aihub-be/issues/631)
- Related: [#398](https://github.com/AiHub-Ecosystem/aihub-be/issues/398), [#632](https://github.com/AiHub-Ecosystem/aihub-be/issues/632), [#1473](https://github.com/AiHub-Ecosystem/aihub-be/issues/1473), [ADR-0076](0076-terminus-readiness-and-opossum-breakers.md), [ADR-0185](0185-adaptive-concurrency-limit-for-ai-service-dispatch.md)

## Context

The per-operation circuit breaker refuses requests while open. As an AI Service recovers, new traffic and client retries can arrive together. Blue-green cutover and rollback can also bring a fresh process with closed breakers into service while the provider is still failing. Production and Sandbox can share the provider's capacity while using separate operational Redis databases. Per-process caps would multiply during this overlap.

The original #631 acceptance criteria also called for pacing API-key cache deletion. The lookup budget introduced by [ADR-0174](0174-bounded-uncached-api-key-lookups.md) now limits PostgreSQL work at authentication. Delaying invalidation would prolong the use of stale authorization after a revocation.

## Decision

**Share a recovery ramp per AI Service capacity pool.** Every operation, tier and slot that uses the pool consumes one budget. Use a dedicated shared Redis connection with a keyspace-scoped ACL following [ADR-0117](0117-prioritize-and-pace-email-outbox-dispatch.md). Use Redis time and atomic updates for phase changes and admission. Keep one half-open probe per operation under [ADR-0076](0076-terminus-readiness-and-opossum-breakers.md). Apply the lowest shared limit when admitting the probe and begin advancing the ramp only once that probe succeeds and the breaker closes. Before a fresh process makes its first dispatch to a protected pool, it also starts the lowest shared phase, even if Redis records the pool as steady. This protects the new slot when the old slot's open breaker is visible only within that process.

Each phase declares a rate in starts per second, a burst and a minimum observation period. Advance one phase at a time after that period has elapsed and a dispatch from the current phase has succeeded. With no success, hold the phase. A provider `5xx`, timeout or throttling response during the ramp returns it to the lowest phase. Late results from an earlier recovery cannot advance the current one. After the final phase meets the same conditions, ordinary admission resumes. [ADR-0185](0185-adaptive-concurrency-limit-for-ai-service-dispatch.md) governs in-flight concurrency throughout.

When Redis cannot confirm admission, refuse dispatch. When Redis is reachable but the state is missing, initialize it atomically at the lowest phase with zero tokens. A lost reply can spend a permit without a dispatch. A permit authorizes one start and cannot be banked for a later burst. With a protected pool enabled, losing the shared coordinator can pause dispatch from both tiers. A healthy cutover can also temporarily reduce throughput because a fresh slot starts the ramp.

**Count starts at the HTTP-client boundary.** First attempts, half-open probes, AIHUB-originated retries and provider result reads all spend a permit when they call that pool. Local polling, stored result replays and requests stopped before the outbound call contribute zero starts. A refused probe leaves the breaker waiting for an actual probe. Count protocol-level HTTP/2 replays separately at the controlled downstream in tests. [ADR-0113](0113-organization-and-service-retry-budgets.md) describes why one AIHUB invocation can produce multiple wire attempts.

Synchronous refusals return retryable `503 AI_SERVICE_UNAVAILABLE` with the existing `retry_after_ms` and `Retry-After` contract. Treat these as local admission refusals in breaker and provider-failure telemetry. Speaking workers obtain admission before recording `dispatch_started_at`. A locally refused job returns to its existing queue with a delay and retains its original 15-minute expiry. It spends no model attempt. A job whose outbound outcome is ambiguous still follows the `DISPATCH_INTERRUPTED` policy in [ADR-0159](0159-async-speaking-grading-job-on-v2-with-bullmq.md).

**Purge API-key cache immediately.** Use the present invalidation behavior in [ADR-0034](0034-organization-api-key-revocation-boundary.md) and the existing uncached-lookup limit in [ADR-0174](0174-bounded-uncached-api-key-lookups.md). With healthy Redis, the limit is 100 PostgreSQL lookups per second and burst 50 per deployment sharing the budget. A process-local positive copy can retain only its original authorization deadline, up to 60 seconds, under [ADR-0114](0114-bounded-identity-cache-tiers.md). Verification of the lookup budget replaces the proposed purge drain, its counter and its alert.

## Acceptance criteria for #631

- Induce a failure that opens the breaker, admit its single half-open probe, and establish a recovery ramp with synthetic rates. Generate new requests and client retries through both tiers against one controlled AI Service. Verify the aggregate cap at every phase, advancement after elapsed time and a successful dispatch, and the return to the lowest phase on provider failure. Verify the bound includes the configured burst. Record AIHUB starts and downstream receipts separately.
- Cut over while the old slot's breaker is open and the provider continues returning `5xx`. Exercise overlapping slots and a rollback that restarts the old slot. Verify the shared cap from the first dispatch by each new process, including when a prior open transition was never published. Exercise Redis loss, missing state, an unconfirmed reservation and a late result from the preceding recovery.
- Verify that a synchronous refusal makes no HTTP call, preserves the public retry hints and records a local refusal. Verify that a Speaking job denied before dispatch is delayed without recording a model attempt and still expires on its original deadline. After an ambiguous send, verify that the worker does not replay the operation.
- Exercise real cache invalidation for 500 warmed API keys and generate cache-eligible requests with cold process-local caches so Redis invalidation produces misses. Count actual PostgreSQL lookups. With healthy Redis, any observed interval of `t` seconds permits at most `50 + 100 × t` lookups under that budget. A single revocation still purges immediately. Grading and Sandbox fresh reads already use the lookup budget and cannot demonstrate a purge-induced miss.
- Expose `aihub_breaker_recovery_admitted_total{downstream}` at `/metrics`. Add a versioned warning and runbook in the [#412 alert catalog](https://github.com/AiHub-Ecosystem/aihub-be/issues/412) for admissions above the active phase allowance, including burst. Use shared admission data for the warning because the active-slot scrape can miss calls from a draining slot. Exercise the alert with a rule fixture and use the controlled downstream test to detect traffic that bypasses the coordinator.
- Run `bun run check:changed` and `bun run verify`. Record the Redis and cutover test results with #631.

## Rollout

Use synthetic limits for implementation and tests. Before enabling a service, record the provider's verified sustainable throughput from [#273](https://github.com/AiHub-Ecosystem/aihub-be/issues/273) and AIHUB's sustainable throughput for the actual topology and operation mix using [#327](https://github.com/AiHub-Ecosystem/aihub-be/issues/327). Set the phase rates and bursts within that evidence. The historical per-process benchmark cannot set current Production thresholds, as [ADR-0167](0167-production-capacity-alerts-and-same-host-response.md) records. This capacity evidence is the rollout prerequisite shared with #632. Completing the rest of the retry-budget work is independent of #631. #398 covers steady-state tenant isolation and #1473 covers jitter on open-breaker refusals.

Deploy configuration readers before writing new Vault keys under [ADR-0128](0128-persisted-values-and-vault-document-keys-are-read-before-they-are-written.md). Activate a pool only once all active, candidate and supported rollback images in both tiers participate in the same gate. A release that can bypass this gate falls below the supported rollback floor while the protection is active.
