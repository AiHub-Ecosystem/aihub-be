# ADR-0016: Durable metering boundary and billing evidence

- Status: Accepted
- Related issues: #9, #56, #57

AIHUB records one durable internal metering record for each request after the API key has resolved the organization and key, including later assertion, validation, downstream, and internal failures; requests that never authenticate have no metering record. The record is written before the response, billability is limited to successful outcomes, and a metering write failure never changes a successful customer response. `request_id` is the uniqueness boundary; billable request units are binary and default to non-billable (deliberately overriding the earlier schema default of one), so an idempotency replay records evidence without charging a second request. Gateway validation/authentication and gateway rate-limit failures are client errors, downstream failures (including provider throttling) are downstream errors, and unexpected failures are internal errors.

AIHUB stores provider-reported aggregate usage and AI-processing timing through a sanitized internal telemetry DTO and never estimates tokens. Each downstream AI Service has a usage-reporting declaration describing whether its current provider contract requires complete token usage. For a model-backed request that actually called a model, `complete` requires valid non-negative input, output, and total aggregates; valid partial values are preserved. When the declaration is enabled, incomplete evidence is `missing_usage`; when it is disabled, incomplete evidence is `not_applicable`, while a complete aggregate is still `complete` even before the declaration is flipped. Requests that fail before a model call and explicitly non-model operations use `not_applicable`, and `quota_unverified` takes precedence when quota admission could not be verified. `metrics.ai_processing_ms` is provider-supplied telemetry and is strongly preferred, but it does not determine token completeness. The AI Speaking contract now specifies the telemetry envelope and its production response has been observed reporting it, so its declaration is enabled. AI Writing telemetry has been observed in dev, but its production contract evidence is still pending, so its declaration remains disabled. Services can be enabled independently. Model identity is outside the provider contract and is not required for metering. Metering remains internal, so public response contracts do not change; provider usage telemetry is coordinated separately with the AI Service contract work.
