# ADR-0020: Invite-only customer-web identity boundary for sandbox MVP

- Status: Superseded by ADR-0046 (the Clerk boundary remains operational until the #94 cutover completes)
- Related issue: #60

The separate Next.js Customer Web, not AIHUB, owns end-user login and sessions. For the first demo, it uses Clerk as the Managed IdP with invite-only passwordless email links; invitations and disables use Clerk's operator tooling, and each Customer User belongs to one Customer Organization with no self-service signup or organization switching. The UI and BFF share one origin. The browser receives only a secure, HttpOnly, same-site session cookie; the BFF evaluates active membership on every request, with a cache no longer than five minutes.

All invited users call one dedicated sandbox AIHUB Organization. Clerk is the membership source of truth; the Customer Web does not duplicate a user table. Clerk invitation links are one-time and provider-expiring; resending an invitation invalidates the previous link, and the Customer Web does not mint invite tokens. The BFF derives an opaque, deterministic Sandbox User ID from the verified Clerk issuer and subject, keeps one Sandbox API key in the deployment secret boundary managed by an operator, mints a fresh assertion immediately before each grading call, and never accepts or exposes credentials or assertion subjects from the browser. Uploaded Speaking audio is pass-through only: the BFF rejects bodies above 25 MiB before forwarding, streams valid audio to AIHUB, aborts the upstream stream when the client disconnects, and discards the audio after the response. The MVP adds no custom session store. Logout clears the local session and invokes the Clerk logout path, so subsequent Live grading requests across tabs are denied; browser-side token cleanup is never treated as authorization. A disabled user loses Live grading access on the next membership decision within the five-minute cache ceiling, while the anonymous mock preview remains available. Login, membership, and credential-mint failures fail closed. Each user action is one grading attempt with no automatic retry; the UI shows a safe error and AIHUB request ID, and logs contain only opaque identifiers, codes, outcomes, and timing. The MVP relies on the sandbox's global quota, rate, and concurrency controls while Live grading remains invite-only. The first release is Sandbox-only; Production configuration is absent until the production organization bridge is approved. Production tenant identity, customer-signed assertions, and self-service onboarding remain outside this decision and belong to #62.
