# AIHUB host and dependency alerts

This is the host/dependency slice contributed by [#474](https://github.com/AiHub-Ecosystem/aihub-be/issues/474) to the broader alert catalog tracked by [#412](https://github.com/AiHub-Ecosystem/aihub-be/issues/412). It does not claim that #412's application, delivery, watchdog, or quarterly-review criteria are complete.

The configured owner label is `aihub-operations`. Routes below were observed in the existing Alertmanager: `warning` goes to `discord-warning`; `critical` goes to `discord-critical`, Pushover, and Telegram. The route is current runtime configuration, not a substitute for #412's severity/notification policy decision. Runbook links point to [AIHUB observability](aihub-observability.md).

| Alert                                 | Condition                                                                                  | Configured severity and route                       | Owner              | Runbook                                               |
| ------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------- | ------------------ | ----------------------------------------------------- |
| `AIHUBHostDiskAbove80Percent`         | Host filesystem use above 80% for 5 minutes                                                | `warning` → `discord-warning`                       | `aihub-operations` | [Host disk](aihub-observability.md#host-disk)         |
| `AIHUBHostMemoryPressure`             | Available host memory below 10% for 5 minutes                                              | `warning` → `discord-warning`                       | `aihub-operations` | [Host memory](aihub-observability.md#host-memory)     |
| `AIHUBContainerOOM`                   | cAdvisor reports an OOM event in the last 10 minutes                                       | `critical` → `discord-critical`, Pushover, Telegram | `aihub-operations` | [Containers](aihub-observability.md#containers)       |
| `AIHUBContainerRestartLoop`           | Container start time changes more than twice in 10 minutes                                 | `warning` → `discord-warning`                       | `aihub-operations` | [Containers](aihub-observability.md#containers)       |
| `AIHUBPostgresConnectionsAboveBudget` | Shared cluster client connections reach 80% of measured `max_connections` for 5 minutes    | `warning` → `discord-warning`                       | `aihub-operations` | [PostgreSQL](aihub-observability.md#postgresql)       |
| `AIHUBRedisMemoryAboveBound`          | Redis memory exceeds 214,748,365 bytes (80% of observed 256 MiB `maxmemory`) for 5 minutes | `warning` → `discord-warning`                       | `aihub-operations` | [Redis](aihub-observability.md#redis)                 |
| `AIHUBRedisCommandLatencyAboveBound`  | Mean Redis command time exceeds 100 ms over 5 minutes, sustained for 5 minutes             | `warning` → `discord-warning`                       | `aihub-operations` | [Redis](aihub-observability.md#redis)                 |
| `AIHUBMonitoringTargetDown`           | Any `aihub-*` Prometheus target is down for 2 minutes                                      | `critical` → `discord-critical`, Pushover, Telegram | `aihub-operations` | [Target health](aihub-observability.md#target-health) |
| `AIHUBCertificateProbeFailed`         | An hourly TLS probe fails for at least 1 minute                                            | `warning` → `discord-warning`                       | `aihub-operations` | [Certificates](aihub-observability.md#certificates)   |
| `AIHUBCertificateExpiresWithin14Days` | A certificate expiry sample is within 14 days                                              | `warning` → `discord-warning`                       | `aihub-operations` | [Certificates](aihub-observability.md#certificates)   |

Disk 80%, PostgreSQL 80% of `max_connections`, and certificate 14 days are defined by #474 and its linked decisions. The remaining thresholds/severity assignments are configured proposals pending #412 review. cAdvisor cannot report stopped-container history. The Redis memory threshold must be updated if the observed `maxmemory` changes. Alert delivery has not been deliberately exercised; do not treat this scoped list as completion of #412.
